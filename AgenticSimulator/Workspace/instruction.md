# 任务目标

你是负责校准源仿真器的 coding agent。通过比较同一固定 policy 在源环境和
目标环境中的表现，修改源物理实现，使源环境产生的行为尽可能接近目标环境。
目标环境保持固定。

物理差异可能来自参数取值、缺失的物理状态或缺失的作用机制。根据实验反馈
判断需要修改什么，使用已有 Isaac Sim / Isaac Lab 接口实现，不修改或重新编译引擎。

校准依据是两侧行为差异是否缩小。任务成功与否只是表现的一部分；即使两侧
都完成任务，也需要检查运动过程是否一致。源侧任务奖励提高本身不能证明校准有效。

# 开始工作

先阅读 `tools.md`，了解实验命令、反馈格式、源物理接口和候选提交方式。
结合 `reference/` 中的只读资料，了解源环境的场景构建、配置加载、policy 的
观测与动作约定，以及物理代码的调用时机。再阅读 `source/` 中的初始物理实现。
参考配置描述的是基准环境；当前候选会在环境创建前修改物理参数，并可在物理
子步中施加额外作用，因此应结合候选代码和实际反馈判断当前源环境的行为。

查询当前预算：

```bash
python scripts/env.py status
```

在修改前获取初始源环境与目标环境的 rollout 反馈，建立比较基准。使用相同的
policy 和回合编号对照两侧表现。每次 rollout 都从新初始化的环境开始，
不延续上次实验的物理状态。

# 观察与推理

利用已公开的源侧状态、轨迹、评价、日志和视频分析源行为；目标侧仅依据宿主
发布的反馈判断。不要尝试读取目标私有配置、内部状态或宿主私有文件。
不要假定未提供的目标信息已经可用。

关注可以在两侧对照的现象，例如运动方向、接触时机、滑动、抓取后的相对运动、
释放后的运动以及任务完成过程。根据实际反馈选择有意义的比较方式，说明
哪些差异来自直接观察，哪些解释仍是假设。

相似的表现可能由不同物理原因产生。将不确定性保留在判断中，用后续实验
区分假设；不要仅凭一个结果就声称恢复了目标的真实参数。

# 工作循环

按以下过程迭代：

观察两侧表现 → 提出物理假设 → 修改源实现 → 执行候选 → 比较反馈 → 修正判断。

- 每次修改前，说明它针对什么现象、预计会怎样改变源行为。
- 优先进行能够判断效果的修改，避免同时改变大量无关因素。
- 执行后检查实际反馈是否支持预期，比较当前候选与初始版本及已有候选。
- 修改无效或使差异增大时，修正实现或恢复更有证据支持的版本。
- 根据实时预算安排实验，为最终候选的执行与比较留出次数。

在 `scratch/` 中记录请求编号、候选编号、修改原因、主要观察和未解决的问题。
可以编写本地分析脚本处理已公开的反馈。保留原始证据，并区分原始记录与
自行计算的比较结果。重复使用已有目标反馈；只有需要新增证据时才再次请求目标实验。

# 修改范围

源物理代码放在 `source/`，分析脚本、笔记和临时文件放在 `scratch/`。
保留 `tools.md` 规定的物理入口和调用约定，可以在源目录内组织必要的辅助模块。

`reference/` 是固定参考资料，修改物理应在 `source/` 中完成。宿主保存候选时
只归档 `source/`，不会将 `reference/` 一起复制到候选运行目录。候选需要的
辅助代码应放在 `source/` 内，不依赖工作区的 `reference/` 路径进行导入。

保持以下内容固定：policy 权重、观测与动作约定、控制周期、任务目标、评价规则
和录像设置。物理改动应体现对动力学或接触过程的解释，不应通过改写观测、
直接回放目标轨迹、调整奖励或加工录像制造一致的反馈。

不要修改只读指令、客户端、参考资料或宿主发布的实验记录。一次只提交一个实验请求，
等待返回后再修改源代码，不在后台并发修改或提交。

失败也是实验记录。根据错误和已有证据决定如何修正，不自动重发通信中断的请求，
不将超时、崩溃或缺少报告直接认定为基础设施故障，也不丢弃失败来夸大结果。

# 完成与提交

当你认为已有充分证据支持当前结果、预算无法支持进一步实验，或无法继续取得
有依据的改进时，从已经执行过的源候选中选择证据最充分的版本。

在 `scratch/` 中保留简要总结：所选候选编号、主要物理改动、支持选择的请求编号
与观察，以及仍存在的差异和不确定性。当前没有自动校准达标阈值，不自行宣称
通过了未提供的验收标准。响应中的 `ok` 仅说明执行状态。

使用源实验返回的候选编号结束会话：

```bash
python scripts/env.py finish --candidate-id <候选编号>
```

提交对应的是宿主已保存的代码版本。若修改后尚未执行，先运行该版本，再选择
其候选编号。没有可提交的候选时，说明原因并使用不带候选编号的 `finish` 结束。
成功结束后停止实验，在最终回复中简要报告候选编号、主要结论和剩余限制。
